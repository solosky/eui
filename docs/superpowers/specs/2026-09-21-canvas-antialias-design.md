# 画布抗锯齿（Anti-Aliasing）— 设计文档

- 日期：2026-09-21
- 分支：`feat/canvas-antialias`（自 `main` 拉出）
- 范围：eui 单仓。不新增依赖，不触碰 motionc（理由见 §2.3）
- 状态：待评审

## 1. 背景

当前画布的形状绘制全部是硬边：

| 原语 | 现状实现 | 抗锯齿 |
|---|---|---|
| `eui_canvas_draw_circle` / `fill_circle` | 中点（Bresenham）圆 + 水平 span 填充 | 无 |
| `eui_canvas_draw_round_rect` / `fill_round_rect` | 四条直线 + 四段中点圆角 | 无 |
| 圆弧 / 圆环 / 扇形 | **不存在** | — |

全仓唯一的亚像素路径是 `src/eui_canvas.c:98` 的 `vlw_blend_pixel()`：16bpp 专用的 RGB565 混合，以 8bit "墨水覆盖度" 混合 VLW 字形，被 `#if EUI_COLOR_DEPTH == 16` 包住。配套的 `canvas_get_pixel()` 也只在 16bpp 下编译出来。低色深字形走的是 `a >= 128` 硬阈值（`src/eui_canvas.c:637`）。

四条决定实现形态的既有事实：

1. **eui 自身不依赖 libm。** `src/`、`include/` 里没有 `math.h`，只有桌面 raylib 驱动链了 `m`（`src/CMakeLists.txt:52`）。AA 必须整数/定点自足。
2. **≤4bpp 的"颜色"是灰度级，不是调色板。** `eui_color_from_rgb` / `eui_color_from_gray` 在各色深下返回的都是灰度量化值：1bpp 二值（亮度阈值 128）、2bpp 4 级、4bpp 16 级、8bpp 256 级。因此低色深的"混合"本质是灰度量化，抖动是唯一能合成中间灰的手段。
3. **抖动在 eui 里不存在，但语义蓝本已有。** VAMeter `app-eui/apps/startup_view.c:92` 的 `sv_apply_dither` 是 4×4 Bayer、阈值 `level*2`、阈值相位锚在屏幕坐标 `x&3/y&3`。本设计把它提升为 eui 内核的规范语义（含相位锚定规则），但**不**改变 VAMeter 侧那份 app 级抖动。
4. **测试面几乎没有像素断言。** `test/canvas/` 下没有一处 `assert` 形状像素（只 dump BMP、`ok = ok &&`）；CI 色深矩阵是 `[1, 8, 16]`，2bpp/4bpp 从未在 CI 里编译运行过。所以本次必须新增像素级契约测试，不能靠"旧测试还绿"来验收。

## 2. 数值方案

### 2.1 为什么不用 `mc_real_t` / Q16.16

曾考虑复用 motionc 的定点设施（`mc_fp_mul` / `mc_fp_div` / `mc_fp_sqrt`）。实测两条硬证据否掉了这条路：

**(a) Q16.16 装不下像素域几何。** `mc_real_t` 定点模式下值域上限是 32767.999：

```
MC_REAL_FROM_INT(57600) = -520093696    /* 编译期 -Winteger-overflow */
MC_REAL_FROM_INT(32768) = -2147483648
```

240×240 画布上圆心到角像素的距离平方是 115200、半径平方 r²=14400（r=120），**任何超过约 181×181 的画布，距离平方在 Q16.16 里直接溢出成负数**。这与 `mc_transition` 里已修掉的 `MC_REAL_FROM_INT(e)`（e ≥ 32768ms 溢出）是同一类 bug：Q16.16 适合归一化量（0..1 的进度/缓动系数），不适合像素域的平方与距离。

**(b) `mc_fp_sqrt` 的定点精度不够 AA 用。** 实测（`src/mc_math.c:55`，8 次固定 Newton）：

| 输入 v | `mc_fp_sqrt` | 精确值 | 误差 |
|---|---|---|---|
| 4000 | 63.245560 | 63.245553 | 0.000006 px |
| 14400（r=120） | 120.047226 | 120.000000 | 0.047 px |
| 20000 | 141.624191 | 141.421356 | 0.203 px |
| 30000 | 174.145142 | 173.205081 | 0.940 px |

AA 覆盖度需要 < 1/16 px = 0.0625 px 的误差，而它在 r=120（240×240 上的典型半径）已经 0.047 px，更大半径崩到 0.2–0.9 px，且**误差是系统性偏置**而非随机抖动——整圈边缘会统一胖/瘦，正是 AA 最怕的方向。根因是种子 `(val + 65536) >> 1` 在大数上离目标太远，8 次迭代里前 6 次都花在折半。

同样这段扫描用纯整数 isqrt（8 位小数）跑 r ≤ 200 全枚举，最大误差 **1/256 px = 0.0039 px**，在 r=120 处比 `mc_fp_sqrt` 准 12 倍，且无值域天花板、无 libm。

`mc_fp_sqrt` 在大输入上的精度衰减是 motionc 自身的潜在质量问题（`mc_vec2_length` 等在大值域下会偏），但它有自己的测试与消费者，**应另开议题，本设计不动它**。

### 2.2 整数方案

几何与覆盖度全部工作在**整数 + 8 位小数的像素单位**（下称 `xx256` = 像素值 << 8）：

```c
/* 逐位法整数开方：返回 floor(sqrt(x) * 2^frac_bits)。无 libm、无浮点、无除法。
 * 约束：x << (2*frac_bits) 必须落在 uint64 内（frac_bits = 8 时 x < 2^48）。
 * 光栅器的实际用法是 frac_bits = 0、radicand 以 (1/256 px)^2 为单位，
 * 于是返回值直接是 1/256 px 单位的半宽（见 §4.1）。 */
static uint32_t aa_isqrt(uint64_t x, uint8_t frac_bits);
```

覆盖度统一用 `cov256 ∈ [0, 256]`（256 = 完全覆盖），只在混合前折算成 `0..255`。

**圆与圆角矩形按行解析扫描线**（§4.1）：每行只算一次 `isqrt`（定出该行"可能有覆盖"的像素区间），行内逐像素只做平方域比较，只有边界像素再算一次 `isqrt` 求解析覆盖度——**内部不做距离测试**。

### 2.3 三角函数

`mc_ease_sine_in_lut[257]` 数值上就是一张四分之一余弦表（实测与 `1 − cos(t·π/2)` 最大偏差 8e-6），但把 easing 表当三角函数读等于让光栅器耦合到 easing 表的内部契约（`scripts/gen_easing_luts.py` 一改就静默坏掉），不可接受；motionc 也没有公开的 `mc_fp_sin/cos`。

圆弧每次调用只需 **2 对** 方向向量（两条端帽的半平面法向，不是每像素），因此：

- eui 内建 **91 项 `sin` 表**（0..90°，`int16` 存 Q14），`cos(θ) = sin(θ + 90°)`，按象限折叠符号——与 `app-eui/ui/ui_draw.c:32` 的 `k_sin_deg[91]` 同一套路，生态内已有先例。
- **不做表内插值**：圆弧 API 的角度参数是整数度（见 §3.3），表在每个可接受角度上都精确，方向向量误差只剩 Q14 量化（1/16384 ≈ 6e-5 rad，在 r=240 上折合 0.015 px）。原本设想的 1° 步长线性插值在这个 API 下是死代码。
- 方向向量以 **Q14** 存（`round(v · 16384)`，`|n| ≤ 16384`）；半平面有符号距离用 32 位中间量即可：`|n_q14 · d256| ≤ 16384 × 81920 = 1.34e9 < INT32_MAX`。

**决策：isqrt 与三角函数私有在 eui**（`src/eui_canvas_aa.c`，约 20 行 + 182 字节表）。motionc 的章程是动画引擎（其 README 自述），整数光栅化开方不是动画数学；这样 eui 的 canvas 保持"只依赖 mc 的动画能力"这条既有边界，也避免为一个 20 行辅助函数做跨仓改动 + 子模块 bump + 100% 覆盖率配测试。

### 2.4 与 `MC_USE_FLOAT` 的关系

`eui_anim` 已经接受"motionc 可能被编成 float"这件事（动画域无所谓）。**光栅器不能**：若 AA 走 `mc_real_t`，`MC_USE_FLOAT` 打开后距离运算变成软件浮点（nRF52 无 FPU），"逐位可复现"契约直接失效。

本设计的 AA 内核**纯整数**，不引用任何 `mc_*` 符号，因此两种模式下画布输出逐位相同。这是一条代码评审不变量（`src/eui_canvas_aa.c` 不 include 任何 `mc_*.h`），也是与 `eui_anim` 有意的区别。

## 3. 架构

### 3.1 分层与文件

新增 `src/eui_canvas_aa.c`，把光栅化从 `src/eui_canvas.c`（1199 行）里分离出来：

| 层 | 内容 | 位置 |
|---|---|---|
| 内部共享工具 | `canvas_set_pixel` / `canvas_get_pixel` 提升为内部头函数（`eui_canvas_px_set` / `eui_canvas_px_get`）；`vlw_blend_pixel` 提升为通用覆盖度混合 `eui_canvas_px_blend` | 新增 `include/eui/eui_canvas_internal.h`，实现留在 `src/eui_canvas.c` |
| 覆盖度内核 | `eui_canvas_isqrt`、sin 表、`eui_canvas_aa_arc`、Bayer 表 | `src/eui_canvas_aa.c` |
| 几何 | 扫描线圆 / 圆角矩形 / 圆环扇形（均归结到 `eui_canvas_aa_arc`） | `src/eui_canvas_aa.c` |
| 公开 API | 四个原地升级 + 三个新入口，全部实现于 AA 文件 | `include/eui/eui_canvas.h`（声明）、`src/eui_canvas_aa.c`（实现） |

`canvas_get_pixel()` 从"仅 16bpp"扩到全色深（低色深抖动同样需要读回 dst）。

### 3.2 混合内核

```c
/* 覆盖度混合：cov 0 → 不写；cov 255 → 直接写 fg；其余读 dst 后按色深混合。
 * 抖动路径的阈值相位锚在 (x, y + canvas->page_y_offset)，跨 PAGE band 连续。
 * cov 取 0..255，与既有的 VLW 字形 alpha 同一量纲，使 16bpp 分支可逐位复用。 */
void eui_canvas_px_blend(eui_canvas_t *c, int16_t x, int16_t y,
                         eui_color_t fg, uint8_t cov);
```

| 色深 | 量化方式 |
|---|---|
| 16bpp | RGB565 逐通道精确混合（与现有 `vlw_blend_pixel` 同式，逐位一致） |
| 8bpp | 灰度线性混合后取整（256 级，无需抖动） |
| 4bpp | 灰度混合后量化到 16 级网格（步长 17） |
| 2bpp | 灰度混合值 + 4×4 Bayer 有序抖动量化到 4 级（步长 85） |
| 1bpp | 同上，量化到 2 级（步长 255） |

统一管线是"先在 0..255 灰度空间算精确混合值 `g`，再量化到目标级数 L"：16bpp 量化是恒等，8bpp 是取整，4/2/1bpp 是网格量化。**抖动只发生在 L ∈ {2, 4}**（即 1bpp、2bpp），与选定范围一致。

抖动量化规格（`t = bayer4[y_abs & 3][x_abs & 3] ∈ [0,15]`，`step = 255/(L-1)`）：

```c
q   = g / step;                        /* 下界级索引 */
rem = g - q * step;                    /* [0, step-1] */
out = (rem * 16 >= (t + 1) * step) ? q + 1 : q;
```

三条性质由构造保证，并各有测试：`rem == 0` 时恒为 `q`（**实心内部不受抖动影响**）、密度随 `rem` 单调（`rem=128, step=255` 时 8/16 格，即 0.5）、抖动至多 +1 级不溢出。

因为颜色进入画布时**已经落在级网格上**（`eui_color_from_gray` / `from_rgb` 的量化就是网格），完全覆盖的像素 `g` 必然 `rem == 0` → 输出精确等于 fg，**实心内部零噪点**。这条是 1bpp 可用性的关键，也是 §6 契约 C10 的第一条。

### 3.3 公开 API

**原地升级**（签名不变，语义变抗锯齿，消费方零改动获益）：

```c
void eui_canvas_draw_circle(eui_canvas_t *canvas, int16_t x, int16_t y, uint16_t r);
void eui_canvas_fill_circle(eui_canvas_t *canvas, int16_t x, int16_t y, uint16_t r);
void eui_canvas_draw_round_rect(eui_canvas_t *canvas, int16_t x, int16_t y,
                                uint16_t w, uint16_t h, uint16_t r);
void eui_canvas_fill_round_rect(eui_canvas_t *canvas, int16_t x, int16_t y,
                                uint16_t w, uint16_t h, uint16_t r);
```

**新增三个入口**（共享同一个内部核 `aa_arc(c, cx, cy, r_out, r_in, a0, a1)`）：

```c
/* 描边占据半径区间 [r - thickness, r]。thickness == 0 → 不画；
 * thickness >= r → 内半径夹到 0，等价于 fill_pie。 */
void eui_canvas_draw_arc(eui_canvas_t *canvas, int16_t cx, int16_t cy,
                         uint16_t r, uint16_t thickness,
                         int16_t start_deg, int16_t end_deg);

/* 描边占据半径区间 [r_inner, r_outer]。r_inner >= r_outer → 不画。 */
void eui_canvas_draw_ring(eui_canvas_t *canvas, int16_t cx, int16_t cy,
                          uint16_t r_outer, uint16_t r_inner,
                          int16_t start_deg, int16_t end_deg);

/* 实心扇形，等价于 draw_ring(r, 0, a0, a1)。 */
void eui_canvas_fill_pie(eui_canvas_t *canvas, int16_t cx, int16_t cy, uint16_t r,
                         int16_t start_deg, int16_t end_deg);
```

保留三个入口而非单入口的理由：`draw_ring` 用双半径、`draw_arc` 用"从 r 向内 t"、`fill_pie` 无厚度概念，各自是仪表盘/环形进度/饼图最直白的表达，读调用点时不必心算 `thickness` 与 `r` 的关系。

**角度语义**（与既有 `ui_draw_rgb565_rot(deg_cw)` 的顺时针度约定对齐）：

- 单位为度，`int16_t`；**0° = 3 点钟方向**，角度增大为顺时针（屏幕 y 向下）。
- 负角合法（`-90, 90` = 上半圆）。
- `delta = end - start`（int16 极差 ±65535）；`delta == 0` → 不画；**`|delta| >= 360` → 整圆**；其余折到 `1..359`（`delta < 0` 时加 360，即画补向的那一侧）。
  （实现落地后修正：原稿写的是 `((end-start)%360+360)%360`，它会把 400° 折成 40°、把 720° 折成"不画"；实际语义取"超过一整圈即整圆"，更符合调用直觉，实施内核按此实现并有测试钉住。）
- 端帽为**平头**（垂直于半径的直边，无圆角），不提供 dash/圆角端帽。
- **已知粒度限制**：整数度意味着半径 r 处的端帽位置以 `r·sin(1°)` 为最小步长——r=120 时 2.1 px、r=60 时 1.05 px。静态仪表盘无影响；按帧推进的环形动画只要每帧步进 > 1°（300ms 转 360° 在 30fps 下约 40°/帧）也无可见台阶，但"每帧 ≤1° 且半径较大"的用法会出现量化抖动。这与既有 `ui_draw_rgb565_rot(deg_cw)` 的整数度约定一致；需要更细粒度时再单独评估（不在本次范围）。

**与 legacy 中点光栅器的差异（有意，需告知消费者）**：新内核把圆心放在**连续点** `(cx, cy)`（像素跨 `[px, px+1]`），与画布既有的 `draw_line` / `draw_rect` / `fill_rect` 索引空间一致；legacy 的中点圆把圆心放在像素中心 `(x+0.5, y+0.5)`。因此 `fill_circle(c, 100, 100, 20)` 现在覆盖列 `[80, 119]`（40 列、左右对称），legacy 覆盖 `[80, 120]`（41 列、不对称）。这是**修正而非位移**，但消费者若断言图形**边缘**像素会看到 1px 差；断言内部像素的不受影响（VAMeter 的既有 smoke 断言就是后者，最终验收时复核）。

## 4. 覆盖度模型（解析扫描线）

### 4.1 圆与圆角矩形

**覆盖度取"到圆的径向距离"，不是单轴弦交叉。** 这是本设计被实测推翻过一次的地方，所以把证据一起留下：先写的是"每行弦半宽算 x 向覆盖度（再乘 ycov 修正极点）"，与 16×16 超采样真值对照，在 r=120 的圆顶行上偏差达 **115/256 = 0.449 px**——圆顶"肩部"真值 241/256、模型给 256/256（抹平），再往外真值 89/256、模型给 0（整段丢失），等于圆顶变平。改用径向距离后同一组半径的最大偏差降到 ≤ 14/256：

| 半径 | 单轴弦模型 | 径向距离模型 |
|---|---|---|
| 4 | 0.234 px | 0.035 px |
| 8 | 0.188 px | 0.039 px |
| 20 | 0.313 px | 0.039 px |
| 120 | 0.449 px | 0.055 px |

（16×16 参考自身分辨率约 11/256，因此径向模型的残余偏差已落在测量精度内。圆顶行剖面：真值 241 / 215 / 123，径向模型 242 / 216 / 125，单轴模型 256 / 256 / 113。）

每行先按**平方域的两个阈值**定出"可能有覆盖"的像素区间，行内逐像素只做平方比较，只有边界像素开方：

```
行 y：dy256 = (y * 256) + 128 - cy256     /* 乘法而非 <<8：坐标可为负，负值左移是 UB */
      外界的平方阈值  ex_out = (r256 + 128)^2      /* d >  r + 0.5 px → 一定不写 */
      内界的平方阈值  in_out = (r256 - 128)^2      /* d <= r - 0.5 px → 全覆盖 */
      b = ex_out - dy256^2
      b <= 0 → 整行跳过
      xout = (aa_isqrt(b, 0) >> 8) + 1     /* 该行可能有覆盖的像素半宽（唯一一次行级 isqrt） */
```

（`ex_out`、`in_out` 的平方项用 64 位中间量：`r256` 最大到 65535×256，`(r256 + 128)^2` 会超 uint32。）

对 `[cx - xout, cx + xout]` 内的每个像素算 `d2 = vx^2 + dy256^2`（`vx = ((x * 256) + 128) - cx256`，像素中心到圆心的有符号偏移），按 `d2` 分三类：

| 条件 | 处理 | 每像素代价 |
|---|---|---|
| `in_in <= d2 <= in_out` | 完全覆盖，`cov256 = 256` → 直接写 fg（不读 dst、不抖动） | 2 次比较 |
| `d2 >= ex_out \|\| d2 <= ex_in` | 完全在外（或完全在孔内）→ 不写 | 2 次比较 |
| 其余（边界带） | `d256 = aa_isqrt(d2, 0)` 为到圆心的径向距离，`cov256 = clamp(128 + r256 - d256, 0, 256)` | 1 次 isqrt |

**没有极点特例**：径向距离模型在圆顶、45°、任意相位下都是同一个公式。局部近似的理论残差是"像素内边界曲率"（弓高 ≈ 1/(8r) px，r=2 时 0.03 px），远小于 1/256 的 isqrt 分辨率；对直线边界（圆弧端帽）该公式是面积精确解。

**成本**：每行 **1** 次 isqrt 定行区间 + 边界带每像素 1 次 isqrt。边界带像素数 ≈ 周长 ≈ 2πr（r=120 时约 750 个，按 ESP32 上逐位 isqrt 约 30 周期估 ≈ 0.1 ms），内部像素只做平方比较与写像素。**内部不做距离测试**这一条因此是构造保证，不是优化。

**与最初设想的差异（落地后修正）**：本设计原稿写的是"每行两次 isqrt（`xin` / `xout`）划出全覆盖区间，实心段整段写出（span 直写）"。落地内核**没有**这两样：行区间只用外界阈值的那**一次** isqrt 定出，全覆盖区间是靠上表第一行的**逐像素平方比较**识别出来的，写也是一次一个像素（`eui_canvas_px_set` / `px_blend`），没有 span 直写。契约不受影响（C2/C3 的语义相同，C13 只描述成本口径），但成本数字变成了"每行 1 次 isqrt"而不是 2 次。

**圆角矩形**：四条直边坐标是整数、覆盖度恒为 256，因此**逐字节等于**现有 `fill_rect` / `draw_line` 的输出（契约 C1）；四个角调用同一个圆核并按象限裁剪，因此与对应四分之一圆**逐像素一致**（契约 C5）。圆角半径夹取逻辑（`w`/`h` 小于 `2r` 时收敛）与现实现保持相同行为。

**角盘圆心必须取"外边界内缩 r"（落地后修正）**：即 `(x+r, y+r)` / `(x+w-r, y+r)` / `(x+w-r, y+h-r)` / `(x+r, y+h-r)`，而**不是**复用直边端点变量 `l/t/ri/b`（`ri = x+w-r-1`、`b = y+h-r-1` 比右/下角心小 1）。拿 `ri`/`b` 当右上/右下/左下角心会让右、下两侧的四段角弧整体内缩 1 px：轮廓在"直边与角弧相切"的那一行/列出现 **1 px 台阶**（`fill_round_rect`），描边版更是 **1 px 断口**（`draw_round_rect` 的角弧接不到直边那一列，轮廓断开）。旧中点光栅器把"含边界点的像素"整格涂满，恰好掩盖了这 1 px，所以这是 AA 化之后才显形的问题；VAMeter 模拟器截图里圆角上的"折角"就是它（契约 C16）。

顺带解决的一个退化配置：`2r == w`（或 `2r == h`）时相邻两角盘圆心**重合**，而圆心是整数意味着两个盘的分界轴落在像素**边界**上——没有像素被轴切开，于是不会被两次部分混合。实测三种退化组合（`2r==w`、`2r==h`、两者同时）与 64 子样本参考的最大偏差 16/256，与非退化配置同量级。

### 4.2 圆环 / 圆弧 / 扇形

同一行模型，只是每个像素多一组径向判据：两条径向边界各折算成**平方阈值**（外边界用 `(r_out ± 0.5)² − dy²`，内边界用 `(r_in ∓ 0.5)² − dy²`，与 §4.1 同式），像素的 `d²` 与之比较后仍分成三类：外侧不写 / 两个边界带（逐像素开方算覆盖度）/ **内外都全覆盖（直接写 fg）**。行区间只由**外**边界的那一次行级 isqrt 定出，内边界不需要额外的行级阈值。

边界带像素的径向覆盖度是两个边的乘积（`d256` 为该像素到圆心的径向距离，1/256 px 单位）：

```
rad_cov256 = (clamp(128 + (r_out256 - d256), 0, 256)
            * clamp(128 + (d256 - r_in256), 0, 256)) >> 8
```

`r_in == 0`（扇形）时内边界永不生效（第二因子恒 256），退化为单边。**已知近似**：仅当一个像素同时跨过内外两条边界（线宽 < 1px）时乘积会低估面积，量级 ~0.1 px；线宽 ≥ 1px 时这是面积精确解。

角度覆盖度见 §4.3，最终覆盖度按乘积逐级缩小：

```
cov256 = ((rad_cov256 * ang_cov256) >> 8)
```

### 4.3 角度覆盖度：交集与并集

端帽边界是**过圆心、沿该端半径方向的直线**（不是垂直于它：`cross(u, v) = |v|·sin(θ_v − θ_u)` 的零集在 `v ∥ u`），法向 `n = (cos θ, sin θ)`（Q14，来自 §2.3 的表）。像素到该直线的有符号距离 `capd256 = (n_q14 · (p256 − c256)) >> 14`，**正方向指向该端帽的外侧**（即不在扇形内的一侧）。半平面覆盖度：

```
cap_cov256 = clamp(128 - capd256, 0, 256)
```

关键在于**扇形的角向覆盖度表达方式随 sweep 改变**：

- `sweep ≤ 180°`：扇形是两条半平面的**交集**，端帽带内取该交集与像素方格的**精确相交面积**。
- `sweep > 180°`：扇形是圆环减去**补扇形**（`360 − sweep < 180°`）→ 先算补扇形的面积覆盖度，再取 `256 − cov`（覆盖率补）。**绝不用"把大弧拆成两段绘制"**：两次带覆盖度混合在同一像素上叠加不是线性关系（`c1 + c2 = 1` 时结果是 `0.25·dst + 0.75·fg`，而正确值是 `0.5·dst + 0.5·fg`），接缝处会明显变暗；单次混合的补扇形公式在端帽线上给出 128/256，因此无接缝（契约 C8）。
- `sweep == 360°`：无端帽 → `ang_cov256 = 256`（等价于 `fill_circle`）。

**面积模型（实施后修正，取代原稿的"两个半平面覆盖度相乘"）：** 原稿让 `ang_cov256 = (cap0 * cap1) >> 8`，即把两条半平面各自的覆盖率相乘当作交集的覆盖率，并把误差记为"~0.1 px、不可辨"。实施期实测推翻了这两点：乘积式在 spec 要求的 sweep 列表上最好情况也是 **57–68/256（≈0.25 px）**，是契约 C15 门槛（24/256）的 2.4–2.8 倍，且失败是**结构性**的而非仅出现在锥尖——`sweep = 1°` 时距圆心仅 3.6 px 的像素（两条端帽线几乎重合处）乘积给 0.22 而真值应为 0；`sweep = 180°` 时两条端帽线是同一条线，乘积把 0.5 平方成 0.25 而真值是 0.5。

实际采用的做法：**端帽带内计算"锥 ∩ 像素"的精确面积**——把像素方格用两条端帽半平面做 Sutherland–Hodgman 裁剪，顶点确定后用鞋带公式求面积（纯定点、仅在端帽那条约 1px 宽带内执行，成本有界）。独立验证（对含锥尖的像素 (0,0)、(−1,−1)、(−1,0)、(0,−1) 以及非锥尖像素，用 256×256 角向窗口积分比对）偏差 **< 0.02/256**；实测该实现使 C15 的扇区偏差降到 6–11/256、圆环 14/256，全部通过门槛。

径向带与角向带仍然各自独立相乘（`(rad_cov256 * ang_cov256) >> 8`）：圆环的"两个径向边相乘"在**线宽 ≥ 1px** 时是面积精确解，仅当线宽 < 1px 使一个像素同时跨过内外两边界时才低估面积（量级 ~0.1 px）。

**曾在退化配置上成立、现已消失的限制（落地后修正）**：`fill_round_rect` / `draw_round_rect` 由"三条矩形 + 四个四分之一圆盘"组成，在 `2r < w` 且 `2r < h` 时子区域逐像素不相交（已被证明）；退化配置 `2r == w` / `2r == h` 曾让相邻两角盘的圆心相差 1 px、共享一列（一行），被共享的像素被两次部分混合（8/16bpp 下 243→254，约 4% 偏暗、1–2px 接缝）。**角盘圆心改为"外边界内缩 r"后两圆心重合，而圆心是整数 → 分界轴落在像素边界上 → 没有像素被轴切开、每个像素整格属于一侧，双重混合不再发生**：三种退化组合实测与参考的最大偏差 16/256（C16 参考门里已把这三组作为常驻用例）。**不要**改用 `r_in = r-1` 绕过：角内部没有任何矩形覆盖，只有该角盘覆盖它，`r_in = r-1` 会在每个角挖出一个 `r x r` 的空洞。

## 5. 契约

标注 `[T]` 的由像素级测试钉住，标注 `[V]` 的由 BMP 画廊人工目检。

| 编号 | 契约 |
|---|---|
| C1 `[T]` | **几何不变**：圆角矩形原语的四条直边像素集合与现实现逐字节一致；四个原语的圆几何（圆心、半径、`draw_circle(r == 0)` 的单点位置）不变，保证消费方不会整体位移一像素。 |
| C2 `[T]` | **内部精确**：`cov == 256` 的像素直接写 fg，不经混合、不读 dst、不抖动。 |
| C3 `[T]` | **未覆盖不写**：`cov == 0` 的像素完全不写，保留原内容。 |
| C4 `[T]` | **边界确实亚像素**：过心水平扫描线上最外圈像素值 ∉ {fg, 原 dst}（16bpp）——专防"看起来 AA 其实还是硬边"。 |
| C5 `[T]` | **对称**：像素中心对齐的圆在 4 个镜像方向逐像素一致；圆角与对应四分之一圆逐像素一致（后者同时钉住圆心算式）。 |
| C6 `[T]` | **无平口**：圆顶/圆底行（`|dy| > r - 0.5`）的"肩部"像素有部分覆盖度，最上/最下行既非整行 fg 也非整行空。径向距离模型下这是自然结果；该测试是防止实现者把它"优化"回单轴弦模型的回归网（后者在此处偏差 0.449 px）。 |
| C7 `[T]` | **单调无振铃**：沿半径方向的覆盖度单调不减。 |
| C8 `[T]` | **一次混合**：任一像素在一次 API 调用内至多被混合一次。测试取 `sweep = 180°` 与 `181°` 的端帽像素，值等于精确单次混合结果（无接缝变暗）。 |
| C9 `[T]` | **角度语义**：负角、`start > end` 跨 0、`sweep == 0` 不画、`sweep == 360` 整圆；`fill_pie(0,360)` 与 `fill_circle`、`draw_ring(r, 0, 0, 360)` 与 `fill_circle` 输出一致。 |
| C10 `[T]` | **抖动**：实心内部零噪点（`rem == 0`）；阈值相位锚在 `(x, y + page_y_offset)`；图形平移 1px → 抖动边缘移动 ≤ 1px；覆盖率递增 → 墨点密度单调不减。 |
| C11 `[T]` | **裁剪**：裁剪外不写；裁剪边界像素与**真实 dst** 混合（不留黑边）。 |
| C12 | **纯整数**：AA 内核不 include 任何 `mc_*.h`、不引入 libm/浮点/随机，`MC_USE_FLOAT` 开启与否输出逐位相同。（代码评审不变量。） |
| C13 `[T]` | **成本模型**：每行 1 次 isqrt（定"可能有覆盖"的行区间）+ 边界带每像素 1 次 isqrt（带 ≈ 2πr 个像素）+ O(面积) 次写；全覆盖区与完全在外区只做平方比较（§4.1 的"与最初设想的差异"）。测试打印 AA 填充的 ns/px 与同面积 `fill_rect` 的 ns/px 之比（不断言绝对阈值，避免 CI 抖动）。 |
| C14 `[T]` | **极端输入**：`r = 0/1/2`、`thickness = 0/1/r/r+10`、`r_inner >= r_outer`、`sweep = 0/1/179/180/181/359/360`、圆心在屏幕外/裁剪外、`w`/`h` < `2r` 的圆角矩形。 |
| C15 `[T]` | **与超采样参考一致**：自带一个 64 子样本参考光栅器，对 `r ∈ {3,4,8,20,60,120}` × 圆心落在像素中心/像素角两种相位，逐像素覆盖度偏差 ≤ 24/256（0.094 px）。实测径向模型 ≤ 14/256，留 1.7 倍余量；单轴弦模型在 r=120 处 115/256，必然失败——这是本设计最重要的判别性测试。 |
| C16 `[T]` | **圆角矩形与参考一致、相切处无缺口**：整体形状（SDF"夹取到内矩形后测距 ≤ r"）的 64 子样本参考，对 `r ∈ {3,6,12,24,42}` 与三种退化组合（`2r==w`/`2r==h`/两者同时）逐像素偏差 ≤ 24/256（实测 ≤ 17/256 / 退化 16/256）；四个相切点外侧紧邻的像素（如 `(x+w-1, y+r-1)`）必须被覆盖（该处真实覆盖度 ≈ 0.997，角心内缩 1 px 时恒为 0）；实心与描边都满足 180° 旋转对称 `(i,j) ↔ (x+w-1-(i-x), y+h-1-(j-y))`（1/2bpp 因抖动相位锚在屏幕坐标而豁免，与 C5 同理由）。 |

既有行为不回归：`draw_circle(r == 0)` 画单点、`fill_round_rect(r == 0)` 等价 `fill_rect`、`fill_circle` 圆心必为 fg 等现有约定保持不变。

## 7. 非目标

- 线段、三角形、文本的 AA（Wu 线、字形亚像素定位）；椭圆、圆角端帽、虚线、旋转/缩放后的 AA、渐变填充。
- **VLW 字形在 ≤4bpp 的 `a >= 128` 阈值改为抖动内核**：这是独立议题，会改掉 `test/font/test_font_vlw_render.c:133` 的"恰好 28 个墨点"精确断言，本设计明确不做。
- 不修改 motionc，包括不修 `mc_fp_sqrt` 的大输入精度衰减（另开议题）。
- 不做形状级缓存/脏矩形优化——每帧重绘的成本由 C13 量化记录，超出预算再另议。

## 8. 风险

1. **圆顶与端帽是最容易做错的地方，且单轴弦模型是一个有吸引力的陷阱**（C6/C8/C15 是回归网）。C15 应先写、先 RED：它对"想省一次 isqrt 而退回单轴弦模型"的优化会立刻报警。TDD 的第一批 RED 建议是 C15 → C8 → C6。
2. **色深矩阵与既有红**（已实测，不再是推测）：全量 `ctest` 只在 1bpp 全绿，8bpp 有 1 个既有夹具红、16bpp 有 2 个、2/4bpp 各 6-7 个（详见 §6 基线）。因此"把全量矩阵扩到 5 档"这个原方案被实测否决：它只会多出红 job，把 AA 的信号埋进既有噪声。改为"全量矩阵保持 3 档 + 专用 job 在 5 个色深只跑 `test_canvas_aa`"，低色深代码仍有真正的门，且红绿完全由本计划的代码决定。
3. **原地升级会改变既有界面的像素输出**：eui 自身无形状像素断言（安全），示例只有 BMP（安全），VAMeter 需实测复核；低性能目标（nRF52）每帧开销上升且无法回退——C13 记录比值，若超预算则改为对 `draw_circle` 保留快路径。
4. **1bpp 的网点感是物理极限**，spec 明确为预期效果；选 4×4 Bayer（16 级阈值）而非 8×8（64 级但 8×8 可见纹理）以与 VAMeter 既有先例一致。
